# Public Release Policy

Frontier Mission Assurance is intentionally source-neutral and suitable for unrestricted public disclosure. The public repository contains the reusable product surface: software, schemas, synthetic examples, documentation, and release evidence.

## Published here

- software and portable schemas;
- synthetic or sanitized test fixtures;
- public documentation and integration guidance;
- generic reference examples;
- release, validation, and provenance evidence intended for public verification.

## Governed elsewhere

Mission-specific and nonpublic information remains in the systems authorized to hold it, including:

- customer, supplier, partner, operator, facility, or program evidence;
- nonpublic architecture, performance, schedule, commercial, contractual, or operational data;
- credentials, secrets, private keys, authentication material, or sensitive security configuration;
- restricted, export-controlled, controlled, classified, or legally protected information;
- screenshots, raw logs, private links, local paths, identifiers, or metadata that reveal protected context.

Operational use with mission evidence belongs in an appropriately access-controlled environment. Public FMA artifacts reference those governed systems through portable contracts and local mappings rather than duplicating protected records.

## Verification scope

FMA validates declared structure, provenance fields, artifact integrity, numerical acceptance criteria, and selected decision-basis relationships. A PASS attests to the controls that ran; scientific validity, operational readiness, compliance, safety, security, and mission approval remain governed by the processes responsible for those determinations.
