# Adoption Path

Orbital Recovery Assurance is designed to enter an existing mission workflow without requiring a central data migration or a replacement of established engineering systems.

The adoption sequence is intentionally direct:

**Evaluate → Map → Count → Exercise → Assess → Decide → Requalify → Learn**

## Evaluate

Use the public repository or verified source archive to run the profile validator, synthetic benchmark, and reference examples before introducing mission-specific data.

## Map

Map only the evidence and state required by the profile from existing governed systems. The Mission Recovery Chain becomes a portable projection over those records:

`Power → Contact → Telemetry → Command → Capability`

Trust and authority remain cross-cutting overlays.

## Count

Count functionally capable **independent recovery paths**, not raw asset totals. Preserve shared roots such as identity, timing, software/update infrastructure, communications, ground capacity, suppliers, configuration, and authority dependencies.

## Exercise

Use synthetic or controlled scenarios to combine technical failure, ambiguous diagnosis, communications degradation, trust degradation, authority uncertainty, and post-intervention evidence gaps.

The exercise identifies the binding constraint before the team commits to an intervention path.

## Assess

Assess the current evidence basis, uncertainty, robust-option membership, option-specific gate state, next-best evidence, expected utility, and requalification obligations.

## Decide

The profile prepares an inspectable decision basis. The governing mission process and accountable human authority make the consequential decision.

## Requalify

After any material intervention, evaluate the changed configuration against the requirements of the intended capability and record the evidence supporting requalification.

## Learn

Promote reusable lessons through governed comparison across cases. Preserve contrary evidence, configuration dependence, and validity limits so local success does not silently become a universal rule.

## Value indicators

The method is creating value when it helps a team:

- expose a material evidence gap before consequential action;
- distinguish physical plausibility from trustworthy, authorized execution;
- reveal shared dependencies that reduce apparent recovery-path diversity;
- identify higher-value evidence before an expensive intervention;
- preserve HOLD when assurance conditions remain unresolved;
- separate technical intervention success from mission requalification;
- reduce Time-to-Trust without weakening the declared assurance basis.

## Resilience rehearsal

Evidence-Degradation exercises test whether contradictory evidence, authority uncertainty, configuration drift, and common-mode evidence dependencies remain visible under pressure. See [`EVIDENCE_DEGRADATION_EXERCISE_PATTERN.md`](EVIDENCE_DEGRADATION_EXERCISE_PATTERN.md).

The rehearsal is designed to expose where evidence architecture, recovery gates, or Time-to-Trust can be strengthened before anomaly response is time-critical.
