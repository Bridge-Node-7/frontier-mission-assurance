# Real-World Adoption Pattern

The intended adoption path is deliberately lightweight.

## Evaluate

A prospective user can clone the public repository, run the profile validator and
synthetic benchmark, and inspect the source without providing mission data.

## Map

The user maps only the fields needed by the profile from existing governed systems.
The public repository does not become the system of record. The Mission Recovery Chain view
(`Power → Contact → Telemetry → Command → Capability`) is created as a projection over those
records, with trust and authority represented as overlays.

## Count and Exercise

The user distinguishes raw asset count from functionally capable independent recovery paths, then exercises the declared chain with synthetic or controlled combinations of technical failure, ambiguous diagnosis, communications loss, trust degradation, and authority uncertainty. The goal is to discover the binding constraint before selecting an intervention.

## Assess

The profile exposes uncertainty, evidence validity, robust-option membership,
option-specific gate status, and requalification obligations.

## Decide

A downstream governed decision workflow and accountable human retain consequential
decision authority.

## Requalify

After any material intervention, the changed configuration is evaluated against the
requirements of the intended capability.

## Learn

Generalized learning is promoted only through a separate governed process. One local
assessment does not automatically become institutional truth.

## Practical success criteria

A real deployment is creating value when it helps a team:

- identify material evidence gaps before consequential action;
- distinguish physical plausibility from trusted/authorized action;
- avoid treating correlated evidence as independent;
- choose a higher-value observation before an expensive intervention;
- preserve a HOLD when assurance conditions remain unresolved;
- prevent a technically successful intervention from being mistaken for a
  requalified mission capability;
- shorten Time-to-Trust without weakening the declared assurance boundary.

## Epistemic-resilience rehearsal

Before relying on the method for a consequential real case, teams can run synthetic Evidence-Degradation exercises to test whether contradictory evidence, authority uncertainty, configuration drift, or common-mode evidence dependencies remain visible and fail closed. See `EVIDENCE_DEGRADATION_EXERCISE_PATTERN.md`.

The purpose is not to prove the mission safe. It is to expose where the organization's evidence architecture, recovery gates, or Time-to-Trust process needs strengthening before a real anomaly.
